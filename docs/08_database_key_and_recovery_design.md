# Database Key & Recovery Design

This document details the production-grade key storage and disaster recovery mechanism implemented for database encryption at rest.

---

## 1. Key Storage Lifecycle (Windows DPAPI)

1.  **Key Generation:**
    *   During the initial startup sequence (if a database does not exist), the `WindowsDpapiKeyProvider` generates a cryptographically secure 256-bit random hex string (64 characters).
2.  **Encryption:**
    *   The raw key buffer is encrypted using Windows Data Protection API (DPAPI) via the `@primno/dpapi` native module.
    *   Scope used is `CurrentUser`, binding the encrypted data specifically to the logged-in Windows user's credentials.
3.  **Persistence:**
    *   The encrypted binary blob is stored at `%APPDATA%/Smart Vyapar/security/database-key.bin`.
4.  **Decryption:**
    *   At boot, the main process decrypts the binary blob using the `CurrentUser` context and loads the raw key string strictly in memory.
    *   Plaintext keys are never written to disk, exposed through IPC, or output in logs.

---

## 2. Disaster Recovery Package Design (scrypt + AES-256-GCM)

Since DPAPI keys become permanently unreadable if the Windows user profile is corrupted or reinstalled, we generate a recovery JSON package.

### Key Derivation Function (KDF)
*   **Algorithm:** `scrypt`
*   **Salt:** Cryptographically random 16 bytes (stored in hex).
*   **Parameters:**
    *   `N = 16384` (CPU/memory cost parameter)
    *   `r = 8` (Block size)
    *   `p = 1` (Parallelization parameter)
*   **Derived Key Length:** 32 bytes (256 bits).

### Cipher Encryption
*   **Algorithm:** `AES-256-GCM` (authenticated encryption)
*   **Initialization Vector (IV):** Cryptographically random 12 bytes.
*   **Authentication Tag:** 16-byte tag generated by GCM (stored in hex).
*   **Integrity Checksum:** SHA-256 hash of the ciphertext.

### JSON Recovery Schema
```json
{
  "version": "1.0.0",
  "timestamp": "2026-08-02T11:12:28.000Z",
  "kdf": {
    "name": "scrypt",
    "salt": "hex-salt",
    "params": { "N": 16384, "r": 8, "p": 1 }
  },
  "crypto": {
    "algorithm": "aes-256-gcm",
    "iv": "hex-iv",
    "tag": "hex-tag",
    "ciphertext": "hex-ciphertext"
  },
  "checksum": "sha256-hash-of-ciphertext"
}
```
If a DPAPI recovery is triggered, the `RecoveryKeyManager` verifies the checksum, derives the KEK using the user's passphrase, decrypts the database key, and updates the local DPAPI binary blob on the host machine.
